# book-log 작업 규칙

## 프로젝트
- 스택: Spring Boot 3.4 / Java 21 / JPA / PostgreSQL(Supabase), 소스는 demo/, 프론트는 frontend/
- 담당 범위: 통합 검색, 하이라이트 모음집, 미니 캘린더, 월별 통계
- Redis 캐싱/비동기는 나중에 하기로 함. 먼저 제안하지 말 것.

## 역할과 진행 방식
- 사용자는 방향을 정하고 결과를 이해·기록하는 역할. 코드는 Claude가 작성.
- 세션당 기능 1개만. 범위 밖 수정 금지, 발견한 문제는 tasks 파일의 "발견 사항"에 적기만 할 것.
- 작업 시작 전 .claude/decisions.md와 해당 tasks/*.md를 먼저 읽을 것.
- 어려운 개념(N+1, Specification, Jackson 직렬화 등)은 코드 주석이 아니라 완료 보고에서 2~3줄로 설명.

## 완료 시 정리
tasks 파일 하단에 아래 형식으로 작성하고, 채팅에는 한두 줄 요약만 남긴다.
1. 문제 상황 2. 고려한 선택지(2~3개) 3. 선택 이유(트레이드오프) 4. 막혔던 부분과 해결
(노션 트러블슈팅에 그대로 옮길 것이므로 짧게, 면접에서 설명 가능한 수준)

## 복습 질문
정리 뒤에 질문 2~3개 (방금 기능 1~2개 + 기존 코드 연결 1개).
사용자가 "모름"이라고 하면 코드 근거로 설명하고, 틀린 답은 코드 기준으로 바로잡는다. 프론트엔드 부분은 내가 안 풀거니까 문제와 답을 같이 줘. 그리고 문제들은 토글로 줘 토글 내부에 답을 적을 수 있도록.

## 면접 대비 모드
"면접 질문해줘"라고 하면 면접관처럼 한 번에 하나씩 질문 → 답변 피드백 → 꼬리 질문.
영역을 지정하면(예: 통계 로직) 그 부분만 깊게 판다.

## 코드/테스트
- 변경 후 ./gradlew test를 실제로 실행하고 결과를 보고한다.
- 테스트는 실제 DB(Supabase)에 붙지 않게 임베디드 H2를 쓴다. 기존 HighlightRepositoryTest는 수정하지 않는다.
- application.yml, application-api-key.yml은 gitignore 대상. 내용을 출력하거나 커밋하지 않는다.
